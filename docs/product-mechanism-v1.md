# 背单词小程序产品机制 V1

## 状态

- 日期：2026-05-20
- 状态：Accepted for V1 planning
- 来源：基于苏格拉底式产品访谈收束

## 产品定位

V1 不是完整英语学习产品，而是一个高密度英中释义记忆训练器。

第一目标是：在 10 分钟内，让学生尽可能多地建立并验证“英文单词 -> 中文释义”的记忆映射。

V1 可以暂时牺牲：

- 例句
- 阅读迁移

V1 需要保留：

- 发音
- 记忆图/场景
- 复习机制
- 听音辨义

## 核心原则

- 固定 3 个词一组。
- 每天最低完成 1 组，上不封顶。
- 完成一组后自动进入下一组，保持训练流。
- 一组不是走完流程就结束，而是本轮错词清空后才结束。
- 只在刚学完后答对一次不算掌握。
- 一个词需要经过本组复习和混组复习验证后，才算本轮掌握。

## 每组流程

每组固定 3 个词，流程如下：

```text
识记 3 个词
-> 本组看词辨义
-> 本组听音辨义
-> 本组完成
```

### 识记阶段

目标：让学生低压力地直接反复看，快速建立初始英中映射。

展示内容：

- 英文单词
- 词性
- 中文释义
- 音标
- 发音
- 记忆图/场景

交互规则：

- 学生点击“已记住 / 还不熟”。
- 自评只记录学习状态，不改变流程。
- 3 个词都看完一轮后，统一进入本组看词辨义。

### 本组看词辨义

目标：验证“看到英文 -> 选中文释义”。

规则：

- 看到英文，选择中文释义。
- 答对：该题型通过。
- 答错：加入本轮错词队列。
- 本轮错词队列清空后，进入本组听音辨义。

### 本组听音辨义

目标：验证“听到发音 -> 选中文释义”。

规则：

- 听到发音，选择中文释义。
- 页面不展示单词拼写，避免从文字猜答案。
- 答对：该题型通过。
- 答错：加入同一个本轮错词队列。
- 本轮错词队列清空后，本组完成。

## 混组复习

混组复习用于避免“刚看完就答对”的假掌握。

触发规则：

```text
第 2 组完成后：6 词混组复习
第 3 组完成后：9 词混组复习
9 词混组完成后：进入新轮次
```

V1 混组题型：

- 看词辨义

说明：混组不再包含听音辨义。听音辨义保留在本组内，用来验证刚学 3 个词的声音到释义映射；混组只承担打乱后的看词辨义，降低流程长度。

## 掌握定义

一个词本轮掌握，需要同时满足：

```text
本组复习答对
+
混组复习答对
```

说明：

- 本组复习答对，代表小范围内能认出来。
- 混组复习答对，代表打乱后仍能认出来。
- 只答对一次不算真正掌握。

## 错词规则

### 本组内

- 看词辨义错和听音辨义错，都进入同一个本轮错词队列。
- 错词必须清空，本组才结束。

### 混组内

- 错哪种题型，就只补哪种题型。
- 本轮内不强制两种题型全部重来。
- 第二天再做综合复测。

## 每日目标

每天最低完成 1 组，上不封顶。

首页需要让学生知道：

```text
今日已完成 X 组
已达成 / 未达成最低目标
```

完成最低目标后仍自动进入下一组。流程页不提示中断学习，避免打断连续答题心流；首页只保留中性的已完成组数和继续学习提示。

## 间隔复习

固定复习节点：

```text
1 天、2 天、4 天、7 天、15 天
```

一个词当天通过后，进入后续间隔复习。

## 每日选词策略

复习词和新词混在一起，不拆成两个入口。

每组 3 个词按综合风险分排序选出：

```text
风险分 = 复习节点 + 间隔时间 + 历史错误次数 + 最近答题结果 + 新词状态
```

新词优先级由连续学习天数决定：

- 连续学习不稳定：优先修复旧词。
- 连续学习稳定：提高新词比例。

## 断签和超期规则

如果学生错过复习窗口，按超期天数决定降级幅度。

建议解释模型：

```text
轻微超期：提高风险分，尽快安排复习
中度超期：退回上一个复习节点
严重超期：退回第 1 天复习阶段
极严重超期：当作未掌握，重新进入 3 词学习流程
```

## 复习失败规则

在 1/2/4/7/15 天复习节点中：

答对：

- 升级到下一个复习节点。

答错：

- 加入当天补救队列。
- 不升级。

补救答对：

- 停留当前节点。
- 重新等待当前节点。

补救再次答错：

- 当作新词重新学。
- 重新进入 3 词学习流程。

## 当前实现对照清单

### 已符合

| 机制 | 当前实现依据 |
| --- | --- |
| 学习单位为 3 个词一组 | `confirmPrecheck` 固定取 `selectedWordIds.slice(0, 3)`，`autoSelectPrecheckWords` 也取 3 个。 |
| 有训前选择/自动选词入口 | `precheck` 页面支持选择、认识/不熟、自动选词、开始识记。 |
| 识记阶段展示词形、音标、词性、释义、记忆图、播放 | `word-study` 页面已展示这些元素，并提供图片模式和播放按钮。 |
| 自评按钮存在 | 识记阶段已有“还不熟 / 已记住”。 |
| 听音辨义存在 | `audio-meaning` 页面已有发音、选项、重播和自动播放逻辑。 |
| 本组看词辨义 | 识记完成后会生成 `group-word-meaning` 题，看到英文选择中文释义。 |
| 本组错词清空 | 本组看词和听音答错都会追加同题型重测题，队列清空后才进入后续环节。 |
| 混组看词辨义 | 混组题目只生成 `mode: "visual"`，不包含听音辨义。 |
| 混组错哪种题型只补哪种 | 答错时追加同一 `mode` 的重测题，不强制两种题型全部重来。 |
| 2 组后 6 词混组、3 组后 9 词混组 | `moveToNextAudioQuestion` 在完成 6/9 个词后触发混组。 |
| 每天最低 1 组，上不封顶的首页提示 | 首页展示“今日至少完成 1 组”和已完成组数。 |
| 学习过程不打断心流 | 本组/混组/听音底部状态栏只展示当前题型和答题反馈，不再提示“可随时结束”。 |
| 本轮掌握判定 | 词状态记录 `groupVisualPassed`、`groupAudioPassed`、`mixedVisualPassed`，三项通过后才进入复习节点。 |
| 复习节点 1/2/4/7/15 天 | 通过本轮掌握后写入 `reviewStage`、`lastReviewAt`、`nextReviewAt`，到期复习词按风险分优先进入每日选词。 |
| 复习失败停留当前节点 | 到期复习词当轮答错会标记 `reviewFailedThisRound`，补救答对后仍停留当前 `reviewStage`，重新等待当前节点。 |
| 断签/超期降级 | 每次开始今日学习会检查超期天数：轻度提高风险，中度退一档，严重退回第 1 天，极严重当作未掌握。 |
| 9 词混组后继续新轮次 | 9 词混组完成后自动生成下一轮候选词，继续保持“最低 1 组，上不封顶”。 |
| 复习节点字段和基础风险排序 | 词状态已预留 `reviewStage`、`nextReviewAt`、`lastReviewAt`，候选词按风险分排序，到期复习词优先。 |
| 学习数据本地持久化 | `storage.js` 使用 `wx.setStorageSync` 保存状态。 |
| 发音在静音模式下播放的基础设置已补齐 | `app.js` 和播放入口使用 `wx.setInnerAudioOption({ obeyMuteSwitch: false, speakerOn: true })`。 |

### 需要改

| 机制 | 当前差距 | 建议开发项 |
| --- | --- | --- |
| 综合风险排序 | 已实现基础风险分，但超期降级、连续学习天数调节仍是粗粒度版本。 | 细化风险公式并增加可测试的阈值配置。 |
| 复习补救再次答错降级为新词 | 当前已能记录失败并停留当前节点，但“补救再次答错直接当新词”还没有单独状态机。 | 为同一复习节点增加补救失败计数，达到阈值后清空 `reviewStage` 和 `nextReviewAt`。 |
| 第二天综合复测 | 到期词已能混入每日选词，但还没有“第二天必须两种题型综合复测”的显式任务标签。 | 每日启动时为到期复习词生成综合复测任务标签，并保留在 3 词组流程中。 |

### 暂不做

| 事项 | 原因 |
| --- | --- |
| 例句展示和例句训练 | V1 目标是快速建立英中释义映射，例句先牺牲。 |
| 阅读理解/完型填空 | 阅读迁移是后续 AI 能力，V1 不作为主流程。 |
| 老师端/教师视角 | 第一版只做学生端，如有老师也使用同一软件通过视频会议共享桌面。 |
| 复杂家长报表 | V1 只保留必要进度，先验证学习闭环。 |
| 全量 30000 词本地打包 | 大词库需要云端词库 + 本地缓存，不应全部放进主包。 |
| 本地音频资源打包 | 音频应走 CDN/云存储 URL，不进入小程序包。 |

## 下一步开发建议

优先级从高到低：

1. 为“补救再次答错 -> 当作新词”增加独立测试和状态字段。
2. 为第二天综合复测增加显式任务标签，方便 UI 提示“这是复习词”。
3. 细化综合风险排序，让连续学习天数明确影响新词比例。
4. 把本地状态迁移到云端用户状态，支持多设备和真实用户规模。
