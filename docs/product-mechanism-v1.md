# 背单词小程序产品机制 V1

## 状态

- 日期：2026-05-20
- 状态：Accepted for V1 planning
- 来源：基于苏格拉底式产品访谈收束

## 产品定位

V1 不是完整英语学习产品，而是一个高密度英中释义记忆训练器。

第一目标是：在 10 分钟内，让学生尽可能多地建立并验证“英文单词 -> 中文释义”的记忆映射。

V1 可以暂时牺牲：

- 例句训练题型
- 阅读迁移

V1 需要保留：

- 发音
- 记忆图/场景
- 例句/搭配的轻量用法辅助
- 复习机制
- 听音辨义

## 核心原则

- 固定 3 个词一组。
- 每天最低完成 1 组，上不封顶。
- 完成一组后自动进入下一组，保持训练流。
- 一组不是走完流程就结束，而是本轮错词清空后才结束。
- 只在刚学完后答对一次不算掌握。
- 一个词需要经过本组复习和混组复习验证后，才算本轮掌握。

## 学习项定义：英文词 + 词性 + 释义块

V1 的最小学习单位不是“英文拼写”，而是：

```text
英文词 lemma + 词性 pos + 中文释义块
```

原因：

- 一个英文词可能有多个词性，不同词性对应的中文义不同。
- 学生可能会 `access n.`，但不会 `access v.`，不能被系统统一算作“会 access”。
- 错词、复习、听音辨义都应该按具体学习项记录，避免状态过粗。

示例：

```text
access
n. 通道；入口；使用权
```

```text
access
v. 获取；进入；存取
```

这两个在系统中算 2 个学习项，也占用 3 个一组里的 2 个名额。

### 展示规则

- 标题只显示英文词，保持页面简洁。
- 词性放在中文释义前，例如 `n. 通道；入口；使用权`。
- 同一个英文词连续出现不同词性时，第二个及后续卡片显示轻提示：`同词不同词性`。
- 如果 PDF 只写了 `n./v.` 但没有把释义按词性分开，系统可以先拆成多个学习项，但必须打 `needs_pos_split_review` 标记，后续人工确认。

### 排序规则

- 初学阶段：同词不同词性紧挨着出现，帮助学生建立“同一个英文词有不同用法”的关联。
- 复习阶段：同词不同词性分散出现，避免学生靠位置或连续记忆猜答案。
- 3 个一组按学习项计数，不按英文词计数。

### 选择题规则

- 单选题的错误选项不使用同一个英文词的其它词性释义。
- 例如当前题是 `access n. 通道；入口；使用权`，错误选项不放 `access v. 获取；进入；存取`。
- 原因是这种题会变成多选或陷阱题，和 V1 的高效识记目标冲突。

## 每组流程

每组固定 3 个词，流程如下：

```text
识记 3 个词
-> 本组看词辨义
-> 本组听音辨义
-> 本组完成
```

### 识记阶段

目标：让学生低压力地直接反复看，快速建立初始英中映射。

展示内容：

- 英文单词
- 词性
- 中文释义
- 音标
- 发音
- 记忆图/场景
- 例句/搭配按钮，默认不展开

交互规则：

- 学生点击“已记住 / 还不熟”。
- 自评只记录学习状态，不改变流程。
- 3 个词都看完一轮后，统一进入本组看词辨义。

### 例句/搭配机制

例句/搭配的目标不是增加新的训练负担，而是帮助学生理解真实用法和常见搭配。

V1 中例句/搭配遵循：

```text
主流程不默认展示
学生点击“例句”后在单词识记卡片内展开
词卡详情页完整展示
不进入本组复习、听音辨义、词汇量测试题型
```

内容来源优先级：

```text
授权学习词典数据库
-> AI 只负责从词典候选中选择最佳内容
-> 词典缺失时，AI 可生成兜底示例
```

权威词典内容规则：

- 英文例句优先来自授权学习词典数据库。
- 英文搭配优先来自授权学习词典数据库。
- 每个学习项最多展示 3 个搭配。
- 每个学习项只展示 1 条最佳例句。
- 最佳例句由 AI 从词典候选中选择，最高优先级是“最能体现当前中文释义”。
- AI 可以评分、排序、选择、解释原因，但不能把词典候选改写后冒充词典内容。

AI 兜底规则：

- 只有在没有权威词典例句/搭配时，才允许 AI 生成英文例句/搭配。
- AI 生成内容必须匹配当前 `英文词 + 词性 + 中文释义块`。
- AI 生成内容不宣称“高频”“真题”“权威”。
- 内测阶段可以展示未人工审核的 AI 兜底内容。
- 上线后，未审核 AI 兜底只对内测用户可见，正式用户不可见。
- 已审核 AI 兜底所有用户可见，但学生端仍保留轻提示：`由 AI 生成`。

中文翻译规则：

- 如果词典自带中文翻译，优先使用词典翻译。
- 如果词典缺少中文翻译，AI 可以补充中文翻译。
- AI 翻译必须以“词义对齐”为优先，尽量显式保留当前学习义项。
- AI 翻译不能反向改变英文例句，也不能把目标词翻成另一个义项。

学生端展示规则：

```text
搭配
最多 3 个

例句
1 条最佳例句 + 中文翻译
```

展示顺序固定为：

```text
先搭配，再例句
```

学生端不展示词典来源、授权批次、AI 选择理由、`translationSource` 等审计信息。内部数据必须保留这些字段，方便上线前质检和授权审计。

建议内部数据结构：

```json
{
  "usage": {
    "collocations": [
      {
        "text": "absolutely right",
        "cn": "完全正确",
        "contentType": "dictionary",
        "source": "authorized_dictionary",
        "sourceBatch": "batch_id",
        "selectedBy": "ai",
        "reviewStatus": "trusted"
      }
    ],
    "example": {
      "en": "You're absolutely right.",
      "cn": "你完全正确。",
      "contentType": "dictionary",
      "source": "authorized_dictionary",
      "translationSource": "dictionary",
      "selectedBy": "ai",
      "reviewStatus": "trusted",
      "senseMatchScore": 0.96
    },
    "aiFallback": {
      "en": "This answer is absolutely correct.",
      "cn": "这个答案完全正确。",
      "contentType": "ai_fallback",
      "reviewStatus": "internal_unreviewed",
      "visibleTo": "beta_only"
    }
  }
}
```

学生端可见性判断：

```text
如果有词典搭配/例句：
  展示词典内容
否则如果是内测用户：
  展示 AI 兜底 + 轻提示“由 AI 生成”
否则如果 AI 兜底已审核：
  展示 AI 兜底 + 轻提示“由 AI 生成”
否则：
  不显示例句入口
```

### 本组看词辨义

目标：验证“看到英文 -> 选中文释义”。

规则：

- 看到英文，选择中文释义。
- 答对：该题型通过。
- 答错：加入本轮错词队列。
- 本轮错词队列清空后，进入本组听音辨义。

### 本组听音辨义

目标：验证“听到发音 -> 选中文释义”。

规则：

- 听到发音，选择中文释义。
- 页面不展示单词拼写，避免从文字猜答案。
- 答对：该题型通过。
- 答错：加入同一个本轮错词队列。
- 本轮错词队列清空后，本组完成。

## 单词和发音策略

### 3000 词上线策略

V1 采用“先全量上线 3000 个基础词”的策略。

上线目标不是等待每个词都精修完成，而是先让完整课标词都能进入当前背词流程：

- 能进入训前检测候选池。
- 能被选入 3 词组。
- 能完成识记、本组看词辨义、本组听音辨义、混组看词辨义。
- 能进入 1/2/4/7/15 天复习机制。

基础可用字段：

```js
{
  id,
  word,
  headword,
  ipa,
  pos,
  cn,
  curriculumStage,
  starLevel,
  sourceIndex,
  tags
}
```

当前本地完整词库已经能生成 3000 个课标词，且 ECDICT 匹配报告为 3000/3000。

小程序包体策略：

- 不把完整富字段词库原样塞进主包。
- 生成 3000 词瘦身版，只保留 V1 背词流程必要字段。
- 全量词典例句、搭配、记忆图 prompt、后续 AI 阅读素材不进入 V1 主包。
- 小程序主包只保留已筛选后的轻量 `usage` 字段：最多 3 个搭配 + 1 条最佳例句/AI 兜底。
- 上线前如果接入云端词库，则本地只保留首屏/离线缓存。

质量策略：

- 先承认 3000 词是“基础可用”，不是“全部精修”。
- 后续按使用频率、错题率、复习风险逐批精修释义和记忆内容。
- 用户体验优先保证流程稳定、候选完整、释义不空、发音可播放。

### 3000 词初始排序

V1 选择按课标阶段排序，而不是从 3000 词随机抽取：

```text
高中必修词 -> 选择性必修词 -> 义务教育基础词
```

对应当前数据字段：

```text
starLevel 1 -> starLevel 2 -> starLevel 0
```

原因：

- 产品目标更贴近高中/高考场景，先覆盖高中必修词。
- 选择性必修词作为第二优先级，保证高中扩展词逐步进入。
- 义务教育基础词放在后面，避免新用户一开始大量遇到过易词。

例外：

- 到期复习词、历史错词、刚降级词仍然优先于新词。
- 也就是说，初始排序只决定“新词池顺序”，不覆盖复习风险排序。

### 同层级内部顺序

词汇量测试只决定从哪个层级开始，不决定同层级内部按字母序学习。

V1 不采用课标词表原始字母序作为学习顺序：

```text
a, ability, able, about...
```

这种顺序像在背字典，容易造成：

- 同首字母单词连续出现，视觉和发音相似度过高。
- 学生误以为课程是机械词表，而不是按学习节奏设计。
- 连续简单词或连续相似词影响训前检测判断。

同层级内部应采用稳定打散顺序：

```text
阶段顺序：由词汇量测试或手动设置决定
阶段内部：稳定打散，不按字母序
复习/错词：仍按风险优先插入
```

稳定打散要求：

- 同一个学生在相同状态下看到的候选顺序稳定，不每次刷新都变。
- 不连续展示大量同首字母词。
- 不破坏 9 词候选窗口和 3 词一组流程。
- 未来可结合词频、难度、错误率做更细的排序。

### 训前检测候选窗口

训前检测一次展示 9 个候选词。V1 选择“同阶段候选窗口”：

```text
同一屏 9 个新词尽量全部来自同一个课标阶段
```

推进顺序：

```text
先展示高中必修词窗口
-> 高中必修词用完后进入选择性必修词窗口
-> 选择性必修词用完后进入义务教育基础词窗口
```

原因：

- 学生在一轮选择里更容易形成“这一批词难度相近”的感受。
- 不把易词和难词随机混在同一屏，减少训前检测时的节奏跳变。
- 适合 3 词一组的流程：从同一阶段的 9 个词里选 3 个不熟词。

复习词插入规则：

- 到期复习词、历史错词、刚降级词允许插入当前 9 词窗口。
- 每个 9 词窗口最多插入 3 个高风险复习词。
- 其余位置仍由当前阶段新词补齐。

建议窗口结构：

```text
最多 3 个复习/错词 + 至少 6 个当前阶段新词
```

原因：

- 不牺牲艾宾浩斯复习机制，避免到期词被饿死。
- 同时保持窗口主体仍是同阶段新词，减少训前检测节奏跳变。

## 词汇量测试机制

### 核心用途

词汇量测试在 V1 中只服务一个核心决策：

```text
判断学生应该从哪个词汇水平开始学
```

测试结果只改变“词库起点/候选池起点”，不直接改变 3 词一组、复习节奏、每日最低组数等主流程。

内部起点仍然保持三档：

```text
义务教育基础词 -> 高中必修词 -> 选择性必修词
```

### 输出形态

V1 采用“双层输出”：

```text
对学生展示：词汇量区间 + 置信说明
对学习流程使用：三档学习起点
```

示例：

```text
当前词汇量约 1500-2100。
这是初测估计，学习 3 天后会结合真实学习表现自动校准。
建议从高中必修词开始。
```

不显示假精确的单点数字，例如 `1837 词`。

原因：

- 学生和家长会认真看词汇量数字，因此不能只给粗糙标签。
- 首测 3-5 分钟无法保证单点数字准确，展示区间更诚实。
- 后续学习行为比单次测试更能反映真实掌握情况。

### 两段式校准

V1 选择“两段式”词汇量判断：

```text
首次 3-5 分钟粗测
-> 给出词汇量区间和学习起点
-> 学习 3 天后结合行为数据自动校准
```

首次测试负责给出初始起点，避免学生一开始学得过难或过易。

后续校准参考：

- 训前检测点“不熟”的比例。
- 本组看词辨义正确率。
- 本组听音辨义正确率。
- 错词回流次数。
- 到期复习通过率。

### 初测题量和结构

首次词汇量测试固定总量为 36 题，但分两段完成：

```text
先做 18 题
根据表现追加 18 题
总题量仍为 36 题
```

原因：

- 36 题比 24/30 题更适合给相对可信的区间。
- 分两段可以先判断大致水平，再把后半段题目投向边界最模糊的层级。
- 总量固定为 36，方便产品节奏、进度条和结果解释。

前 18 题采用平均分层抽样：

```text
义务教育基础词：6 题
高中必修词：6 题
选择性必修词：6 题
```

每次进入词汇量测试都会重新生成一组题目，同一次测试内题目保持稳定：

```text
重新进入测试：重新抽题
测试进行中：不临时换题
```

原因：

- 前半段先均衡探测三个层级，不预设学生水平。
- 每层 6 题足够形成初步通过率，但不把低水平学生困在大量高难题里。
- 后半段再把题量投向临界层级，提高最终区间和起点判断的可信度。
- 多次测试如果题目完全相同，学生会记住答案，无法体现真实水平。

后 18 题集中追加到“临界层级”：

```text
如果某一层前 6 题表现接近通过/不通过边界，
后 18 题优先追加该层题目。
```

示例：

```text
高中必修词 4/6 对
=> 高中必修层级可能是学习起点分界
=> 后 18 题追加更多高中必修题
```

临界判定：

```text
某层前 6 题答对 3 题或 4 题，视为临界层级。
```

原因：

- `3/6` 和 `4/6` 最接近会/不会边界。
- `0-2/6` 更像明显未掌握。
- `5-6/6` 更像明显通过。

多个层级同时临界时：

```text
更低临界层追加 12 题
更高临界层追加 6 题
```

示例：

```text
义务教育基础词：5/6
高中必修词：4/6
选择性必修词：3/6

后 18 题：
高中必修词 12 题
选择性必修词 6 题
```

原因：

- 更低层级决定“是否会被高估”，优先保障起点不太难。
- 更高层级保留跳级判断空间，但不让它主导后半段。

没有临界层时，按“最高明显通过层”和“最低明显失败层”处理。

如果学生明显卡在两层之间：

```text
义务教育基础词：6/6
高中必修词：5/6
选择性必修词：1/6

后 18 题：
高中必修词 12 题
选择性必修词 6 题
```

原因：

- 最高通过层决定当前相对可靠的学习基础。
- 最低失败层决定是否可以进入下一层。
- 12/6 分配更保守，优先避免把学生放到过难起点。

如果学生连基础层也明显不稳：

```text
义务教育基础词：2/6
高中必修词：0/6
选择性必修词：0/6

后 18 题：
义务教育基础词 18 题
```

原因：

- 此时继续测高中层意义不大，只会增加挫败感和噪声。
- 后半段用于尽量准确估计基础词汇量。

### 测试题型和计分口径

V1 词汇量测试题型：

```text
看到英文 -> 选择中文释义
```

选项包含：

```text
1 个正确释义
3 个干扰释义
1 个“不认识”
```

原因：

- 该题型最贴近 V1 核心目标：快速建立英文词形和中文释义的映射。
- “不认识”选项可以降低学生乱猜带来的虚高。
- V1 暂不在词汇量测试中加入听音辨义，避免把发音能力混入词汇量估计。

计分口径：

```text
选“不认识”和选错干扰项，在起点判断中都算未掌握。
```

但结果报告需要区分：

```text
不认识率：学生主动承认没见过/没记住。
误选率：学生选择了错误释义，存在词义混淆。
```

解释口径：

- 不认识率高：主要是词汇缺口，需要从对应层级补词。
- 误选率高：主要是词义映射不稳，需要更多辨义和复习。

### 分层通过阈值

各层通过阈值不同：

```text
义务教育基础词：80%
高中必修词：70%
选择性必修词：60%
```

原因：

- 越基础的层级越应该扎实，义务教育基础词需要更高通过率。
- 高中必修词允许少量不稳，但仍要达到相对可靠的掌握。
- 选择性必修词属于更高阶词，允许更大的缺口，用于判断是否具备挑战下一层的基础。

### 学习起点映射

学习起点按“第一个未通过层”决定：

```text
义务教育基础词未通过
=> 从义务教育基础词开始

义务教育基础词通过，高中必修词未通过
=> 从高中必修词开始

义务教育基础词通过，高中必修词通过，选择性必修词未通过
=> 从选择性必修词开始

三层都通过
=> 从选择性必修词开始，继续巩固高阶词
```

如果义务教育基础词也未通过，不新增更低层级：

```text
仍从义务教育基础词开始，
结果提示“基础词需要补强”。
```

原因：

- 当前 V1 词库只划分三层，暂不引入小学/更基础层。
- 学习起点逻辑应简单可解释：未通过哪一层，就从哪一层学。
- 对低水平学生，先从义务教育基础词开始即可，后续由 3 词组流程降低压力。

### 词汇量区间估算

V1 不输出单点词汇量，而是输出区间：

```text
词汇量下限 - 词汇量上限
```

上限采用偏乐观估算：

```text
通过层：该层词量全计
未通过层：该层词量 * 该层正确率
```

下限采用保守估算：

```text
通过层：该层词量全计
未通过层：该层词量 * 该层正确率 * 0.5
```

示例：

```text
义务教育基础词：1500 词，正确率 83%，通过
高中必修词：499 词，正确率 55%，未通过
选择性必修词：1001 词，正确率 20%，未通过

上限 = 1500 + 499 * 0.55 + 1001 * 0.20
下限 = 1500 + 499 * 0.55 * 0.5 + 1001 * 0.20 * 0.5
```

原因：

- 上限反映“通过层稳定掌握，未通过层按短测正确率部分贡献”。
- 下限避免把未通过层的短测正确率全部当成稳定掌握。
- 通过层全计，符合“这一层已经达到进入下一层的要求”的产品解释。

词汇量测试完成后，写入用户画像状态：

```js
{

    startLevel,
    vocabularyRange: {

    },

        passed
      },
      required: {
        total,

        passed
      },
      selective: {
        total,
        correct,

        wrongChoice,

```

其中：

```text

```

原始答题记录仍可进入答题日志，但用户画像长期只需要保留：

- 学习起点。
- 词汇量区间。
- 每层正确率。
- 每层不认识率。
- 每层误选率。

原因：

- 这些字段足够支持结果页解释、候选池起点和后续 3 天校准。
- 不把用户画像膨胀成完整答题明细，后续接云端时更轻。

### 对候选池的影响

词汇量测试结果默认立即影响训前检测候选池：

```text
startLevel = foundation
=> 候选池从义务教育基础词开始

startLevel = required
=> 候选池从高中必修词开始

startLevel = selective
=> 候选池从选择性必修词开始
```

同时保留用户手动调整起点的能力：

```text
默认按建议起点开始
用户可在水平设置中调整
```

原因：

- 测试结果必须真正改变学习体验，否则测试会显得没有价值。
- 允许手动调整，避免学生或家长对结果不认同时被系统锁死。
- 手动调整只改变新词候选池起点，不改变到期复习词和错词优先级。

### 3 天后校准原则

学习 3 天后，系统结合真实学习行为校准词汇量。

默认校准：

```text
更新展示的词汇量区间
```

只有在学生明显过难或过易时，才调整学习起点：

```text
明显过难
=> 降低新词候选池起点

明显过易
=> 提高新词候选池起点
```

原则：

- 不频繁移动学生学习路径，避免破坏连续性。
- 测试结果负责初始定位，真实学习数据负责慢慢修正。
- 起点调整只在错配明显时发生。

明显过难规则：

满足以下任意 2 项，就降低新词候选池起点：

```text
训前检测不熟率 > 70%
本组看词辨义正确率 < 60%
听音辨义正确率 < 50%
错词回流率 > 40%
```

明显过易规则：

满足以下任意 2 项，就提高新词候选池起点：

```text
训前检测不熟率 < 20%
本组看词辨义正确率 > 85%
听音辨义正确率 > 80%
错词回流率 < 10%
```

### V1 目标

发音在 V1 中承担两个作用：

- 建立“英文单词 -> 声音”的稳定关联。
- 训练“听到发音 -> 选择中文释义”的听音辨义。

V1 暂不做学生跟读、录音评分、音素纠错。这类能力复杂度高，且不直接服务“10 分钟内记住更多中文释义”的第一目标。

### 发音形态

- 默认使用英音。
- V1 不提供英音/美音切换，避免学生在初始记忆阶段被多个声音锚点干扰。
- 识记页展示音标；听音辨义页不展示单词拼写和音标，只允许播放/重播和选择中文释义。

### 音频来源

- 测试号阶段：动态拼接在线词典发音链接，优先验证学习体验。
- 上线前升级：迁移到自有或授权音频资源，音频文件走 CDN/云存储，不进入小程序主包。

### 单词数据字段

测试号阶段可以动态拼接音频 URL，不强制把 `audioUrl` 写入词库。

上线前升级为稳定字段：

```js
{
  word: "absolutely",
  ipa: "/'aebselu:tli/",
  accent: "uk",
  audioUrl: "https://cdn.example.com/audio/uk/absolutely.mp3"
}
```

上线前需要确认：

- 音频版权或授权边界。
- CDN/云存储路径规则。
- 缓存策略和失败重试策略。
- 词库构建脚本如何批量生成并校验 `audioUrl`。

## 混组复习

混组复习用于避免“刚看完就答对”的假掌握。

触发规则：

```text
第 2 组完成后：6 词混组复习
第 3 组完成后：9 词混组复习
9 词混组完成后：进入新轮次
```

V1 混组题型：

- 看词辨义

说明：混组不再包含听音辨义。听音辨义保留在本组内，用来验证刚学 3 个词的声音到释义映射；混组只承担打乱后的看词辨义，降低流程长度。

## 掌握定义

一个词本轮掌握，需要同时满足：

```text
本组复习答对
+
混组复习答对
```

说明：

- 本组复习答对，代表小范围内能认出来。
- 混组复习答对，代表打乱后仍能认出来。
- 只答对一次不算真正掌握。

## 错词规则

### 本组内

- 看词辨义错和听音辨义错，都进入同一个本轮错词队列。
- 错词必须清空，本组才结束。

### 混组内

- 错哪种题型，就只补哪种题型。
- 本轮内不强制两种题型全部重来。
- 第二天再做综合复测。

## 每日目标

每天最低完成 1 组，上不封顶。

首页需要让学生知道：

```text
今日已完成 X 组
已达成 / 未达成最低目标
```

完成最低目标后仍自动进入下一组。流程页不提示中断学习，避免打断连续答题心流；首页只保留中性的已完成组数和继续学习提示。

## 间隔复习

固定复习节点：

```text
1 天、2 天、4 天、7 天、15 天
```

一个词当天通过后，进入后续间隔复习。

## 每日选词策略

复习词和新词混在一起，不拆成两个入口。

每组 3 个词按综合风险分排序选出：

```text
风险分 = 复习节点 + 间隔时间 + 历史错误次数 + 最近答题结果 + 新词状态
```

新词优先级由连续学习天数决定：

- 连续学习不稳定：优先修复旧词。
- 连续学习稳定：提高新词比例。

## 断签和超期规则

如果学生错过复习窗口，按超期天数决定降级幅度。

建议解释模型：

```text
轻微超期：提高风险分，尽快安排复习
中度超期：退回上一个复习节点
严重超期：退回第 1 天复习阶段
极严重超期：当作未掌握，重新进入 3 词学习流程
```

## 复习失败规则

在 1/2/4/7/15 天复习节点中：

答对：

- 升级到下一个复习节点。

答错：

- 加入当天补救队列。
- 不升级。

补救答对：

- 停留当前节点。
- 重新等待当前节点。

补救再次答错：

- 当作新词重新学。
- 重新进入 3 词学习流程。
