# 背单词小程序产品机制 V1

## 状态

- 日期：2026-05-20
- 状态：Accepted for V1 planning
- 来源：基于苏格拉底式产品访谈收束

## 产品定位

V1 不是完整英语学习产品，而是一个高密度英中释义记忆训练器。

第一目标是：在 10 分钟内，让学生尽可能多地建立并验证“英文单词 -> 中文释义”的记忆映射。

V1 可以暂时牺牲：

- 例句
- 阅读迁移

V1 需要保留：

- 发音
- 记忆图/场景
- 复习机制
- 听音辨义

## 核心原则

- 固定 3 个词一组。
- 每天最低完成 1 组，上不封顶。
- 完成一组后自动进入下一组，保持训练流。
- 一组不是走完流程就结束，而是本轮错词清空后才结束。
- 只在刚学完后答对一次不算掌握。
- 一个词需要经过本组复习和混组复习验证后，才算本轮掌握。

## 每组流程

每组固定 3 个词，流程如下：

```text
识记 3 个词
-> 本组看词辨义
-> 本组听音辨义
-> 本组完成
```

### 识记阶段

目标：让学生低压力地直接反复看，快速建立初始英中映射。

展示内容：

- 英文单词
- 词性
- 中文释义
- 音标
- 发音
- 记忆图/场景

交互规则：

- 学生点击“已记住 / 还不熟”。
- 自评只记录学习状态，不改变流程。
- 3 个词都看完一轮后，统一进入本组看词辨义。

### 本组看词辨义

目标：验证“看到英文 -> 选中文释义”。

规则：

- 看到英文，选择中文释义。
- 答对：该题型通过。
- 答错：加入本轮错词队列。
- 本轮错词队列清空后，进入本组听音辨义。

### 本组听音辨义

目标：验证“听到发音 -> 选中文释义”。

规则：

- 听到发音，选择中文释义。
- 页面不展示单词拼写，避免从文字猜答案。
- 答对：该题型通过。
- 答错：加入同一个本轮错词队列。
- 本轮错词队列清空后，本组完成。

## 单词和发音策略

### 3000 词上线策略

V1 采用“先全量上线 3000 个基础词”的策略。

上线目标不是等待每个词都精修完成，而是先让完整课标词都能进入当前背词流程：

- 能进入训前检测候选池。
- 能被选入 3 词组。
- 能完成识记、本组看词辨义、本组听音辨义、混组看词辨义。
- 能进入 1/2/4/7/15 天复习机制。

基础可用字段：

```js
{
  id,
  word,
  headword,
  ipa,
  pos,
  cn,
  curriculumStage,
  starLevel,
  sourceIndex,
  tags
}
```

当前本地完整词库已经能生成 3000 个课标词，且 ECDICT 匹配报告为 3000/3000。

小程序包体策略：

- 不把完整富字段词库原样塞进主包。
- 生成 3000 词瘦身版，只保留 V1 背词流程必要字段。
- 例句、搭配、记忆图 prompt、后续 AI 阅读素材不进入 V1 主包。
- 上线前如果接入云端词库，则本地只保留首屏/离线缓存。

质量策略：

- 先承认 3000 词是“基础可用”，不是“全部精修”。
- 后续按使用频率、错题率、复习风险逐批精修释义和记忆内容。
- 用户体验优先保证流程稳定、候选完整、释义不空、发音可播放。

### 3000 词初始排序

V1 选择按课标阶段排序，而不是从 3000 词随机抽取：

```text
高中必修词 -> 选择性必修词 -> 义务教育基础词
```

对应当前数据字段：

```text
starLevel 1 -> starLevel 2 -> starLevel 0
```

原因：

- 产品目标更贴近高中/高考场景，先覆盖高中必修词。
- 选择性必修词作为第二优先级，保证高中扩展词逐步进入。
- 义务教育基础词放在后面，避免新用户一开始大量遇到过易词。

例外：

- 到期复习词、历史错词、刚降级词仍然优先于新词。
- 也就是说，初始排序只决定“新词池顺序”，不覆盖复习风险排序。

### 训前检测候选窗口

训前检测一次展示 9 个候选词。V1 选择“同阶段候选窗口”：

```text
同一屏 9 个新词尽量全部来自同一个课标阶段
```

推进顺序：

```text
先展示高中必修词窗口
-> 高中必修词用完后进入选择性必修词窗口
-> 选择性必修词用完后进入义务教育基础词窗口
```

原因：

- 学生在一轮选择里更容易形成“这一批词难度相近”的感受。
- 不把易词和难词随机混在同一屏，减少训前检测时的节奏跳变。
- 适合 3 词一组的流程：从同一阶段的 9 个词里选 3 个不熟词。

复习词插入规则：

- 到期复习词、历史错词、刚降级词允许插入当前 9 词窗口。
- 每个 9 词窗口最多插入 3 个高风险复习词。
- 其余位置仍由当前阶段新词补齐。

建议窗口结构：

```text
最多 3 个复习/错词 + 至少 6 个当前阶段新词
```

原因：

- 不牺牲艾宾浩斯复习机制，避免到期词被饿死。
- 同时保持窗口主体仍是同阶段新词，减少训前检测节奏跳变。

### V1 目标

发音在 V1 中承担两个作用：

- 建立“英文单词 -> 声音”的稳定关联。
- 训练“听到发音 -> 选择中文释义”的听音辨义。

V1 暂不做学生跟读、录音评分、音素纠错。这类能力复杂度高，且不直接服务“10 分钟内记住更多中文释义”的第一目标。

### 发音形态

- 默认使用英音。
- V1 不提供英音/美音切换，避免学生在初始记忆阶段被多个声音锚点干扰。
- 识记页展示音标；听音辨义页不展示单词拼写和音标，只允许播放/重播和选择中文释义。

### 音频来源

- 测试号阶段：动态拼接在线词典发音链接，优先验证学习体验。
- 上线前升级：迁移到自有或授权音频资源，音频文件走 CDN/云存储，不进入小程序主包。

### 单词数据字段

测试号阶段可以动态拼接音频 URL，不强制把 `audioUrl` 写入词库。

上线前升级为稳定字段：

```js
{
  word: "absolutely",
  ipa: "/'aebselu:tli/",
  accent: "uk",
  audioUrl: "https://cdn.example.com/audio/uk/absolutely.mp3"
}
```

上线前需要确认：

- 音频版权或授权边界。
- CDN/云存储路径规则。
- 缓存策略和失败重试策略。
- 词库构建脚本如何批量生成并校验 `audioUrl`。

## 混组复习

混组复习用于避免“刚看完就答对”的假掌握。

触发规则：

```text
第 2 组完成后：6 词混组复习
第 3 组完成后：9 词混组复习
9 词混组完成后：进入新轮次
```

V1 混组题型：

- 看词辨义

说明：混组不再包含听音辨义。听音辨义保留在本组内，用来验证刚学 3 个词的声音到释义映射；混组只承担打乱后的看词辨义，降低流程长度。

## 掌握定义

一个词本轮掌握，需要同时满足：

```text
本组复习答对
+
混组复习答对
```

说明：

- 本组复习答对，代表小范围内能认出来。
- 混组复习答对，代表打乱后仍能认出来。
- 只答对一次不算真正掌握。

## 错词规则

### 本组内

- 看词辨义错和听音辨义错，都进入同一个本轮错词队列。
- 错词必须清空，本组才结束。

### 混组内

- 错哪种题型，就只补哪种题型。
- 本轮内不强制两种题型全部重来。
- 第二天再做综合复测。

## 每日目标

每天最低完成 1 组，上不封顶。

首页需要让学生知道：

```text
今日已完成 X 组
已达成 / 未达成最低目标
```

完成最低目标后仍自动进入下一组。流程页不提示中断学习，避免打断连续答题心流；首页只保留中性的已完成组数和继续学习提示。

## 间隔复习

固定复习节点：

```text
1 天、2 天、4 天、7 天、15 天
```

一个词当天通过后，进入后续间隔复习。

## 每日选词策略

复习词和新词混在一起，不拆成两个入口。

每组 3 个词按综合风险分排序选出：

```text
风险分 = 复习节点 + 间隔时间 + 历史错误次数 + 最近答题结果 + 新词状态
```

新词优先级由连续学习天数决定：

- 连续学习不稳定：优先修复旧词。
- 连续学习稳定：提高新词比例。

## 断签和超期规则

如果学生错过复习窗口，按超期天数决定降级幅度。

建议解释模型：

```text
轻微超期：提高风险分，尽快安排复习
中度超期：退回上一个复习节点
严重超期：退回第 1 天复习阶段
极严重超期：当作未掌握，重新进入 3 词学习流程
```

## 复习失败规则

在 1/2/4/7/15 天复习节点中：

答对：

- 升级到下一个复习节点。

答错：

- 加入当天补救队列。
- 不升级。

补救答对：

- 停留当前节点。
- 重新等待当前节点。

补救再次答错：

- 当作新词重新学。
- 重新进入 3 词学习流程。

| 机制 | 当前差距 | 建议开发项 |
| --- | --- | --- |

| 第二天综合复测 | 到期词已能混入每日选词，但还没有“第二天必须两种题型综合复测”的显式任务标签。 | 每日启动时为到期复习词生成综合复测任务标签，并保留在 3 词组流程中。 |

### 暂不做

| 事项 | 原因 |
| --- | --- |
| 例句展示和例句训练 | V1 目标是快速建立英中释义映射，例句先牺牲。 |
| 阅读理解/完型填空 | 阅读迁移是后续 AI 能力，V1 不作为主流程。 |
| 老师端/教师视角 | 第一版只做学生端，如有老师也使用同一软件通过视频会议共享桌面。 |
| 复杂家长报表 | V1 只保留必要进度，先验证学习闭环。 |
| 全量 30000 词本地打包 | 大词库需要云端词库 + 本地缓存，不应全部放进主包。 |
| 本地音频资源打包 | 音频应走 CDN/云存储 URL，不进入小程序包。 |

## 下一步开发建议

优先级从高到低：

1. 为“补救再次答错 -> 当作新词”增加独立测试和状态字段。
2. 为第二天综合复测增加显式任务标签，方便 UI 提示“这是复习词”。
3. 细化综合风险排序，让连续学习天数明确影响新词比例。
4. 上线前升级音频方案：授权英音音频、CDN/云存储、`audioUrl` 字段、批量校验脚本。
5. 把本地状态迁移到云端用户状态，支持多设备和真实用户规模。
