# 专注力设计指南

日期：2026-05-31

---

## 核心理念

背单词的专注力不来自"提醒用户集中注意力"，而来自**消除一切让用户分心的东西**。

用户在背词时的理想状态是：看到词 → 反应 → 下一个。循环速度越快，掌控感越强，越容易进入心流。任何需要用户"扫描页面找到下一步该做什么"的设计，都是专注力的敌人。

---

## 原则一：一屏一件事

### 问题

当前识记页同时展示：单词、音标、释义、播放按钮、图片开关、例句开关、跟读状态、记忆图、"再听听"、"记住了"。用户的眼睛要在 8-10 个元素之间跳转，每个元素都在竞争注意力。

### 做法

学习页面上，视觉焦点永远只有一个——**当前单词**。

#### 识记页改造

- 单词大字居中，占据屏幕视觉中心（垂直居中，不是顶部）。
- 音标紧跟单词下方，作为单词的一部分，不是独立元素。
- 释义在单词下方，字号明显小于单词，形成层次。
- 去掉播放按钮。发音由自动循环驱动，用户不需要手动触发。
- 图片、例句、搭配全部藏在"下拉展开"或"点击词卡详情"里，默认不展示。
- 记忆图不默认展开。只在用户主动请求时出现。
- 底部只保留一个按钮："记住了"。"再听听"用下拉手势或轻点屏幕空白区域触发，不占固定按钮位。
- 跟读状态用极小的图标或动画暗示，不占文字行。

#### 复习页改造

- 本组复习：只展示单词和音标，其他全部隐藏。2秒后自动揭示释义。
- 听音辨义：只展示播放图标（一个圆），其他全部隐藏。
- 看中文回忆英文：只展示中文释义，其他全部隐藏。
- 混组复习：和本组复习完全一样的界面，用户无感知这是"混组"。

## 原则二：渐进揭示，速度即快感

### 问题

当前本组复习用选择题（看英文选中文），用户的注意力被 4 个选项分散。选择题本质上是"扫描→排除→点击"，认知负担重，速度慢。

### 做法

用"回忆→揭示"替代选择题。快速节奏创造掌控感。

#### 时间轴

```
T=0s   展示英文 + 音标 + 自动播放
       （用户脑中回忆释义）

T=2s   自动揭示释义
       （用户确认自己想得对不对）

       用户点击"记住了" → 立刻下一个
       用户未操作 → 3秒后自动下一个 + 加入错词本
```

#### 关键细节

- 2 秒揭示时间可以随学习阶段缩短。初期 2 秒，后期可以 1.5 秒甚至 1 秒。
- 揭示用"从下往上推入"的微动画，不是突然出现，也不是淡入。推入更有"翻牌"的体感。
- "记住了"按钮在揭示前就可以点击。如果用户在 2 秒内点击，说明确实记住了，记为高置信通过。
- 不展示"回答正确"的中间状态。点击即切换，零停留。

## 原则三：隐藏复杂度，只暴露下一步

### 问题

当前混组复习页展示"6 个混组记忆""打乱前面学过的词""第 1 组 + 第 2 组 混组复习""混组看词辨义""混组抽查：看到英文，选择中文释义"。这些信息是给开发者看的，不是给学生看的。学生不需要知道什么是"混组"，什么是"大 group"，自己正在第几组。

### 做法

用户只需要知道三件事：

1. 当前是哪个词
2. 大概还有多少（用圆点感知，不用数字）
3. 做完了没有

#### 进度表达

不用"2/6""第 3 组"这种文字进度。用一排小圆点：

- 已完成 = 实心主题色
- 当前 = 实心 + 脉动动画
- 未完成 = 空心/灰色

圆点数量就是剩余词数，用户扫一眼就知道还有多少，不需要阅读文字。

#### 阶段切换

本组复习 → 听音辨义 → 看中文回忆英文 → 混组复习，这四个环节的切换对用户应该是无感的。不弹过渡页，不说"进入听音辨义"。只在进度圆点的风格上做微妙区分（比如圆点变成三角、变色），让用户隐约感知到"节奏变了"，但不需要主动理解。

#### 不说的话

以下文案应该从学习页面完全移除：

- "3 个一组即时复习"
- "混组看词辨义"
- "混组抽查：看到英文，选择中文释义"
- "6 个词 · 打乱前面学过的词"
- "第 1 组 + 第 2 组 混组复习"
- "本组识记已完成"
- "回答正确"/"已加入本轮错词"

## 四条执行规则

### 规则一：学习页无额外业务导航

进入学习流程后，页面主体内隐藏底部 Tab 和次要入口，只保留一个轻量返回按钮。用户可以通过返回按钮退出，也可以通过"暂停"手势（比如长按屏幕、或从左边缘右滑）暂停。

小程序默认系统导航栏仍然保留。它负责微信容器级返回、安全区、状态栏和胶囊按钮适配，不参与学习页面的视觉复刻。

学习主体内也保留一个轻量返回按钮。它不参与主要学习操作，但保证学生或家长在任意环节都能明确退出当前页面。

原因：小程序面向学生和家长，明确可见的返回路径比绝对沉浸更重要。返回按钮要轻量，不抢当前单词的视觉焦点。

暂停后弹出简洁的暂停面板：

```
已学 6 / 45 词

继续学习
暂停休息
调整计划
```

### 规则二：单词垂直居中

所有学习页面，当前单词永远垂直居中。不是顶部 1/3 处，是真正的视觉中心。

- 识记：单词居中 + 释义在下方
- 本组复习：单词居中，释义从下方推入
- 听音辨义：播放图标居中
- 看中文回忆英文：中文释义居中

这让用户的视线锚定在屏幕中心，不需要上下移动。

### 规则三：零等待过渡

答对 → 立刻切换下一个词，不弹"回答正确"。
答错 → 展示正确答案 1 秒 → 自动切换。
一组完成 → 直接进入下一阶段，不弹"本组完成"。

每多停留 1 秒，就多一次"我要不要休息一下"的念头。零等待保持惯性。

唯一的例外：一个 list 全部完成时，展示完成动画和学习报告。这是奖励节点，值得停留。

### 规则四：进度用体感，不用数字

- 进度条/圆点用颜色填充表达，不用"6/15""第 3 组"。
- 播放循环用小圆点闪烁表达，不用"2/3 次"文字。
- 错词加入用屏幕边缘一闪红光表达，不用"已加入错词本"文字。
- 完成一组用全屏微振动或色块膨胀表达，不用弹窗文字。

## 颜色与氛围

### 学习页背景

当前所有页面背景一致（#faf9f5 暖米白）。建议学习流程内的页面使用更深的、更"沉浸"的背景：

- 学习页面背景：#141413（接近纯黑）或 #1a1f1a（深墨绿）
- 单词颜色：#faf9f5（白色/米白）
- 释义颜色：rgba(250,249,245,0.7)（半透明白）
- 按钮颜色：保留 #d97757（橙棕色）

深色背景的好处：

1. 自然隔绝手机通知栏、状态栏的干扰
2. 让白色文字成为唯一视觉焦点
3. 营造"阅读模式"的专注氛围
4. 减少夜间使用的刺眼感（配合睡前复习场景）

首页和"我的"保持浅色，学习页面切换到深色，形成"进入专注模式"的体感。

### 可选：提供浅色/深色切换

如果不想强制深色，可以：

- 默认深色
- 在"我的"设置里提供"学习页面主题"切换
- 睡前复习窗口自动切换深色

## 动效原则

### 要做的动效

- 词卡切换：水平滑动（当前词滑出，下一个词滑入），200ms
- 释义揭示：从下往上推入，150ms
- 进度圆点：当前词的圆点有脉动呼吸动画
- 答错反馈：屏幕边缘闪一次红色光晕，300ms
- 一组完成：进度圆点全部变色 + 轻微振动
- 一个 list 完成：全屏庆祝动画

### 不做的动效

- 弹窗淡入淡出（弹窗本身就不应该出现在学习页）
- 按钮按下缩放（增加响应延迟感）
- 页面切换的复杂过渡（学习页之间应该是瞬切）
- 任何需要用户等待的动画

## 与 v2 设计文档的关系

本指南是 `product-mechanism-v2.md` 的视觉/交互补充。v2 定义了"做什么"（回忆→揭示、循环播放、错词本），本指南定义了"怎么做才能让用户专注"。

核心差异：v2 文档里仍然保留了一些提示文案（如"2s 内没有点击记住"、"提示学生跟读"），本指南建议这些提示用视觉暗示（动画、颜色、倒计时进度条）替代文字，减少阅读负担。
