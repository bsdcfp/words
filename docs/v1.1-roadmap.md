# 单词小程序 v1.1 路线图

## 状态

- 日期：2026-06-09
- 状态：Draft（待你确认范围 / 排期）
- 来源：v1.0 发版前代码梳理，识别 14 项「定义了但没接上 / 占位 / 装饰」
- 原则：先把**半成品接活**（ROI 最高），再做**诚实度提升**，最后扩范围

---

## 1. 背景

v1.0 发版采取「原样打标签」策略——已知有几项历史欠债没修。CHANGELOG 列了 5 条，完整梳理下来其实是 14 条，分三类：

| 类别 | 数量 | 特点 |
|---|---|---|
| 🔴 看着实现了，其实不工作 | 4 | 代码写了一半、UI 没接 / 关键函数没被调用 |
| 🟡 假入口 / 装饰文案 | 6 | 表面有功能、点了无效或文案是装饰 |
| 🟢 字段定义了没用 | 4 | state 里有字段、全代码无读写 |

v1.1 目标：**让产品声称的功能与代码现实一致**。不再「画一个看起来完整的产品 + 标注已知限制」。

---

## 2. 总览（按 ROI 排序）

```
P0 接通半成品     →  改 UI 而非改逻辑，单项 0.5-1 天，体验立竿见影
P1 真实化占位     →  涉及新逻辑/数据，单项 1-3 天
P2 范围扩展        →  需要数据/设计投入，单项 3+ 天
停车场            →  v1.1 不做，留 v1.2 评估
```

---

## 3. P0 — 接通半成品（高优）

### 3.1 接通 SRS / 遗忘曲线复习 🔴

**现状**：核心算法 `nextReviewPatch(current)`（计算下次复习日期）**零调用**。`reviewStage` / `nextReviewAt` 永远是 0 / null → `getDueReviewWordIds` 永远空 → 「遗忘曲线复习」功能实际不存在，UI 也没入口。

**改动点**：
- `miniprogram/utils/study-flow.js`：在 `answerChoiceQuestion` 答对路径里调用 `Object.assign(answeredState, isCorrect && isRoundMastered(...) ? nextReviewPatch(current) : {})`，让一轮掌握后真正写入排期。
- `miniprogram/pages/index/index.wxml`：「我的」或「错词本」页加「遗忘曲线复习」入口，复用 `startForgettingReview` handler（handler 已存在但 0 处绑定）。
- `tests/study-flow.test.mjs`：新增 3-5 条断言（答对→`nextReviewAt` 有值；到期可拿到；间隔 1→2→4→7→15 升级）。

**验收**：手动跑通——学完 9 词、隔天 `getDueReviewWordIds` 能返回到期词、复习答对后 `reviewStage+1`。

**估**：1 天。

---

### 3.2 接 3 个学习页开关 UI 🔴

**现状**：`studyAudioEnabled` / `studyImageMode` / `studyUsageOpen` 三个状态在 JS 里被 7+ 处读写，对应的 `toggleStudyAudio` / `toggleStudyImageMode` / `toggleStudyUsage` 三个 handler 也都在，但 **WXML 0 处绑定**——音频默认常开、关不掉；图片模式 / 释义展开根本没法切。

**改动点**：
- `miniprogram/pages/index/index.wxml`：在 `view == 'word-study'` 的 `focus-topbar` 加 3 个图标按钮（喇叭 / 图片 / 释义），分别 `bindtap` 三个 handler。
- `miniprogram/pages/index/index.wxss`：新加 `.icon-volume-on` `.icon-volume-off` `.icon-image-toggle` `.icon-usage` 4 个 CSS 图标。

**验收**：识记页点喇叭能静音、点图片切图文模式、点释义展开/收起。

**估**：0.5 天。

---

### 3.3 进度分母统一 🔴

**现状**：实际词库 3368 词，但代码里 `displayTotal = Math.max(total, 3500)` 强制锚到 3500：
- 首页文字 `progressText: ${learned} / ${wordDatasetMeta.total}` → 显示 "120 / 3368"
- 百分比 `progressPercent = learnedCount / displayTotal` → 按 3500 算
- 同屏两个分母，且 **100% 永远不可达**（学完 3368 也只到 96%）

**改动点**：
- `miniprogram/pages/index/index.js` 的 `buildHomeData` / `buildProfileData` / `buildReportData`：删掉所有 `displayTotal = Math.max(...)`，统一用 `wordDatasetMeta.total`。
- 同时砍掉 `wordDatasetMeta.miniProgramTotal`（同一份数据的另一个变量）。

**验收**：首页文字与百分比分母一致；学完全部词时 100%。

**估**：0.5 小时。

---

## 4. P1 — 真实化占位（诚实度）

### 4.1 真积分系统 MVP 🟡

**现状**：每日成果页固定显示「专注之星 +120 积分」（写死）。state 里没有 points/tokens 字段。

**改动点**：按 [`docs/points-token-economy-design.md`](points-token-economy-design.md) 落地 P0 阶段：
- `state.user` 加 4 字段：`points` / `pointsTotal` / `pointsToday` / `pointsTodayKey`
- 加 `awardPoints(state, reason, amount)` 统一计分（含跨日重置 + 每日上限 300）
- 在 6 个事件挂点：首次记住新词 / 复习答对 / 完成 List / 打卡 / 错词巩固 / 阶段测
- 成果页改用**真实**积分明细
- 顶部加积分胶囊（可选 P0.5）

**待你定**（设计文档第 10 节）：6 项数值、每日上限。

**验收**：完成一个 List 显示真实分数；明细可拆（10×9 新词 + 30 完成 + 20 打卡 = 140）；跨日重置。

**估**：2-3 天。

---

### 4.2 真称号体系 🟡

**现状**：UI 上的「专注之星」是占位、从不发放。代码里只有 2 个真实称号：「起步徽章」「三日连学」。

**改动点**：
- 新增 5-6 个**有真实条件**的称号，与积分里程碑挂钩（如「七日连学」「错词清零 30」「单日 +200 积分」）。
- `completeCurrentList` 等关键事件检查条件、写入 `state.user.badges`。
- 成果页「专注之星」改为**本次解锁的真实称号**（无则不显示徽章块）。

**待你定**：具体称号清单 + 解锁条件。

**估**：1 天（依赖 4.1 的事件挂点）。

---

### 4.3 错词提醒推送 🟡

**现状**：设置里有 `wrongReminderEnabled` + `wrongReminderTime: "19:00"`，但代码里**找不到 `requestSubscribeMessage` 任何调用**——设置存了、提醒没接。

**改动点**：
- 微信「订阅消息」一次性 / 多次订阅授权，每次发起需要用户点击。
- 后端发推送（小程序订阅消息要服务端调用）—— **这条会引入后端依赖**，纯前端跑不通。
- 前端改：完成一个 List 时弹「明天 19:00 提醒你复习错词」订阅授权。

**风险**：纯前端可做的只有「触发授权 + 记录订阅 token」。真发推送需要后端。

**待你定**：v1.1 上后端推送，还是仅做前端授权 UI 并标注「需配后端」？

**估**：前端 1 天；后端另算。

---

### 4.4 阶段测三种技能模式 🟡

**现状**：月度页阶段测卡显示三个标签「看词辨义 / 听音辨义 / 中文回忆英文」，但代码里阶段测**只用一种模式**（`createChoiceQuestion` 默认 `"visual"`）。

**改动点**：
- `startStageTest`：把 N 题分成 3 段，每段 mode 不同。
- 复用现有 `audio-meaning` / `meaning-recall` 题目模板渲染。
- 题数动态分配（如 20 题 = 7 / 7 / 6）。

**验收**：阶段测过程中三种题型轮换；结果页按技能分别报正确率。

**估**：1.5 天。

---

## 5. P2 — 范围扩展

### 5.1 开放更多词书 🟡

**现状**：7 个水平选项里 6 个标「暂未开放」。**只有「高中」能用**。

**改动**：补数据 + 题库。每个词书是一份 `data/words.js` 级别的数据，加上音频。

**待你定**：v1.1 开放哪几个？建议：**初中**（覆盖率高）+ **大学四级**（用户多）；考研/雅思留 v2。

**估**：每个词书 3-5 天（数据准备主导）。

---

### 5.2 收藏功能上线 🟢

**现状**：`defaultWordState.favorite: false` 字段存在，**全代码无任何读写**。

**改动**：词卡详情页加爱心按钮 + 我的页加「收藏夹」入口（复用错词本 UI）。

**估**：1 天。

---

### 5.3 AI 内容消费场景接入 Token 🟡

**现状**：词卡有 AI fallback 数据（usage.js 里 `aiFallback`），但所有用户的 `userType` 未初始化 → `isBetaUser` 永远 true → 门形同虚设；也无消费。

**改动**：按经济文档 P2：
- AI 例句 / 助记入口按钮（灰态显示「X Token 解锁」）
- 接 Token 扣费，先 mock AI 跑通，再接真实生成
- 词典已有内容免费、AI 生成才扣

**前置**：依赖 4.1（积分→Token 兑换）

**估**：3-5 天（取决于是否接真 AI）。

## 6. 停车场（v1.1 不做）

- ⏸ **跟读录音真实分析**：当前 `onFrameRecorded` 只判断有没有声音、不评分。真发音评估要接语音 API。
- ⏸ **折线图周/月/年切换**：现在只有周聚合。
- ⏸ **暂停面板「调整计划」**：当前是跳转到我的页，不是真的"今日调整"。
- ⏸ **错词本批量操作**：当前只有"移除"，没有「全选 / 批量复习选中」。
- ⏸ **睡眠/起床时间生效**：当前只是存设置、没做免打扰/排课。
- ⏸ **userType 字段初始化 + 升级流程**：与 5.3 关联，等 5.3 一起。

## 8. 完成定义（DoD）

每条 P0 / P1 项必须满足：
- ✅ `npm test` 全绿
- ✅ `npm run audit:interactions` 通过
- ✅ 至少 1 条新增测试断言（如适用）
- ✅ 无 `console.log` / TODO 残留
- ✅ CHANGELOG 对应条目更新

发版门禁：所有 P0 完成 + 至少 80% P1 完成 → 切 v1.1.0 标签。

## 9. 优先级总结（一图流）

```
P0  接通 SRS               [1 天]   ⬅ 最重要：核心学习价值，且是死的
    接 3 个学习页开关       [0.5 天] ⬅ 性价比最高：纯加 UI
    进度分母统一            [0.5 小时] ⬅ 一行代码、诚实度立刻 +1
                                  ────────────────
                                  P0 总计 ≈ 2 天
P1  真积分 MVP              [2-3 天]
    真称号                  [1 天]
    错词推送（前端）         [1 天]
    阶段测三技能            [1.5 天]
                                  ────────────────
                                  P1 总计 ≈ 5-7 天
P2  开放词书（初中+四级）    [6-10 天]
    收藏                    [1 天]
    AI Token 消费           [3-5 天]
                                  ────────────────
                                  P2 总计 ≈ 10-16 天
```

**保守预估**：P0 + P1 共 7-9 天可交付 v1.1。
